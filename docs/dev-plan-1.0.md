# v1.0 开发计划

> 版本主题：「校历自主与数据出口」。范围沿 2026-10-23 讨论确定（1.0 = 学期设置 + 提醒可配置 + ICS 导出）。
> 计划制定时基线：v0.9.1 / versionCode 22，README 记录 87 项 JVM 单元测试，开工时以实际重跑结果为准。
> 本地 `.github` 目录未见 workflow 文件，发布路径以 `tools/dev` 脚本与实际配置核实为准。
> 以下为开发与验收计划；与前版计划（dev-plan-0.9.md）冲突处，以本文件为准。

## 范围内功能

| # | 功能 | 预估 | 依赖 |
| --- | --- | --- | --- |
| 1 | 应用内学期设置（开学日期 + 总周数，含 TermConfig 重构） | 2.5–3.5 天 | 基线重跑与依赖检查 |
| 2 | 上课提醒提前量可配置（5–30 分钟及关闭） | 0.5–1 天 | 无（可与功能 1 并行） |
| 3 | ICS 日历导出（按周展开为日历事件） | 1–1.5 天 | 功能 1（导出需读取学期配置） |

**明确排除**（本版不做）：多学期管理、作息表编辑（节次时间 / 每日节数）、Excel / CSV 导入导出、ICS 导入、周视图小组件、下节课卡片、课程搜索、备份系统分享（FileProvider）、云同步、空教室查询、Material You 动态取色。多学期与作息编辑是 1.1 候选主线。

## 实施顺序

```
TermConfig 注入重构 → 学期设置 UI 与冲突处理 → 提醒提前量 → ICS 导出 → 回归与发布
```

功能 1 的重构必须最先做：`TermCalendar` 当前是硬编码 `object`，被 10+ 处引用（课表 / 日程 / 课程编辑、TodayPlan、BackupCodec、GridScheduleParser、提醒与小组件链路）。先把"学期配置"变成可注入的纯数据，再叠 UI，避免边做边改调用点。功能 2 独立，可穿插在功能 1 的等待窗口完成。功能 3 依赖功能 1 落定后的 TermConfig 读法，放最后。

## 功能 1：应用内学期设置

**目标**：开学日期与总周数可在"我的"页配置并持久化；周次计算、日期表头、提醒、小组件、教务导入与备份校验全部改读该配置。默认值等于现硬编码值（2026-09-07 / 17 周），升级用户零行为变化。

**现状与风险**：`TermCalendar.TERM_START` 为编译期常量，dev-plan-0.9 已明确遗留风险——2027 年 2-3 月下学期开学后周次与日期全部错位且无法用户侧修复。本功能是 1.0 的核心，其余功能均为陪衬。

**实现要点**：

- 新增纯 JVM 数据类 `TermConfig(startDate: LocalDate, totalWeeks: Int)`，放 `data/TermConfig.kt`；校验：`totalWeeks` 在 1..30；`startDate` 在 2020-01-01..2035-12-31（防误选）。
- `TermCalendar` 重构为接收 `TermConfig` 的纯函数集：`currentWeek(term, today)`、`weekDates(term, week)`、`isCurrentWeek(term, week)`，删除常量属性。不保留旧静态入口，强制改完所有调用点。
- 调用点逐一注入（已核对清单）：`TodayPlan`、`BackupCodec`、`GridScheduleParser`、`ScheduleFragment`、`OverviewFragment`、`CourseFragment`、`CourseDetailSheet`、`EditCourseActivity`、`ReminderReceiver`。UI 侧经 `MainViewModel` 暴露 term StateFlow；`ReminderReceiver` 与小组件无 ViewModel，直接读偏好。
- 持久化沿用 `ThemePreferences` 模式新增 `TermPreferences`（SharedPreferences 文件 `term`，键 `start_date` / `total_weeks`，缺省回退默认值）；写入后触发 `ReminderReceiver.reschedule` 与小组件刷新。
- UI 入口放"我的"页：Material DatePicker 选日期 + 总周数选择；**选到非周一时明确提示并自动对齐到所在周周一**（TermCalendar 语义为"第 1 周周一"）；保存前预览"第 1 周周一日期"与"按新配置今天处于第几周"，用户确认后写入。
- **总周数缩小的存量冲突**：若有课程周次超出新范围，保存前弹窗列出受影响课程，二选一——"自动剪掉越界周次"（Room 事务内裁剪，显示修改条数，沿用 CourseRepository mutationMutex）或"取消修改"。不允许静默保留越界周次：`BackupCodec.validateCourses` 会因 weeks 越界拒绝导出，形成隐性死锁。
- 备份协议维持 `version=1` 不变：导出时 term 块写当前配置；恢复时要求与当前配置完全一致，不一致明确提示"备份学期与当前学期设置不一致"。学期修改后，旧学期备份被拒是预期行为，写入发布说明。
- `GridScheduleParser` 按日期推算实验课周次改用当前配置；`SampleData` 首次播种与 `SeedPolicy` 不动（默认配置下语义不变）。

**验收标准**：

- [ ] 修改开学日后：周次编号、表头日期、"今天"高亮、日程页、小组件头部、课前提醒全部按新配置重算；无需重启
- [ ] 配置重启后保留；0.9.1 覆盖安装后默认值与现行为完全一致（周次、提醒、备份可恢复）
- [ ] 选非周一日期时对齐提示正确；总周数越界（0 / 31）被拦截
- [ ] 缩小总周数时冲突课程逐条列出；确认裁剪为事务操作，取消则不写任何数据
- [ ] 学期修改后导出的备份含新 term 块；用旧学期备份恢复被拒且提示原因；往返（round-trip）无损
- [ ] TermConfig 校验、周一对齐、冲突裁剪判定有 JVM 单测；现有 87 项测试全部保持通过

## 功能 2：提醒提前量可配置

**目标**：课前提醒提前量可在 5 / 10 / 15 / 20 / 30 分钟与"关闭"之间选择，默认 20 分钟（现值），重启保留。

**实现要点**：

- 新增 `ReminderPreferences`（SharedPreferences 文件 `reminder`，键 `lead_minutes`，`-1` 表示关闭）。
- `ReminderReceiver.scheduleFor` 与 `showNotification` 读取配置；`TodayPlan` 的提前量从常量改为参数传入（`REMIND_MINUTES` 保留为默认值常量）。课表页 / 小组件的"即将上课"标记与闹钟共用同一配置，行为一致。
- 选"关闭"时跳过课程闹钟注册，但保留每日重算与小组件刷新链路（同一次广播已承载两者，只裁剪闹钟部分）；通知权限被拒的现有静默逻辑不变。
- 入口放"我的"页单选对话框；修改后立即 `reschedule`，不等到下一次课程变更。

**验收标准**：

- [ ] 各档位下闹钟触发时间与设置一致；"关闭"后不再收到提醒，小组件与每日刷新不受影响
- [ ] 修改即时生效，重启保留；未授权精确闹钟时降级为普通提醒的行为不回归
- [ ] 提前量计算（含"关闭"分支）有 JVM 单测

## 功能 3：ICS 日历导出

**目标**：把整份课表导出为标准 `.ics` 文件（RFC 5545），用户导入系统日历 / Google 日历后可获得系统级课程提醒，作为应用内提醒的补充出口。

**实现要点**：

- 新增纯 JVM `data/ics/IcsComposer.kt`：输入课程快照 + `TermConfig` + 作息表，输出 VCALENDAR 文本。不依赖 Android API，全部逻辑可 JVM 单测。
- 事件展开采用**逐周展开**：每门课每个上课周次生成一个 VEVENT；`DTSTART` = `weekDates(term, week)[dayOfWeek-1]` + 起始节次时间，`DTEND` = 下课时间。采用浮动本地时间（不写 TZID），中国无夏令时，语义足够。
- 不用 RRULE 归并：离散周次集合（如 1-8、11 周）本就需拆多段，逐周展开更简单、可逐条核对；30 门课 × 17 周 ≈ 500 事件，体积无压力。
- 字段映射：`SUMMARY` = 课程名；`LOCATION` = 教室；`DESCRIPTION` = 教师 + "第 X 周"；`UID` = `classschedule-{courseId}-{week}-{day}` 稳定可复现。**跳过 `hiddenWeeks` 对应周次**（隐藏 = 不出现在日历），在 README 说明。
- 严格按 RFC 5545：CRLF 行尾、75 字节折行（不得切断多字节字符，中文名必须覆盖测试）、转义 `\n , ;`、`PRODID` / `VERSION:2.0` / `CALSCALE:GREGORIAN`、UTF-8 无 BOM。
- 分发沿用备份导出路径：SAF `CreateDocument`，MIME `text/calendar`，默认文件名 `classschedule-{yyyyMMdd}.ics`；一次性读取完整快照（复用备份导出的快照读取约定），编码与写文件离开主线程；上限保护对齐备份（5 MiB / 10,000 条）。
- 不含 VALARM：提醒方式交由日历客户端设置；不写 `METHOD`，重复导入的行为由日历 App 决定（可能产生重复事件），此限制写入 README。

**验收标准**：

- [ ] 导出文件可被系统日历与 Google 日历导入，日期、时间、星期与课表逐条一致
- [ ] 含中文 / 逗号 / 分号 / 换行的课程名转义正确；折行不断裂多字节字符；行尾为 CRLF
- [ ] 空课表可导出（仅日历头）；hiddenWeeks 周次不出现在事件中
- [ ] IcsComposer 的日期推算（weekDates × dayOfWeek）、节次时间映射、转义、折行、上限均有 JVM 单测

## 风险提示

- **硬截止**：下学期预计 2027 年 2-3 月开学，学期设置必须在寒假前发布，否则周次错位且无法用户侧修复。排期从发布日倒推，功能 1 优先级最高，功能 2 / 3 可裁剪出 1.0。
- **重构波及面**：TermConfig 注入涉及 10+ 调用点，含提醒与小组件后台链路；M0 完成后必须全量回归（切周、提醒、小组件、教务导入），再做 UI。
- **备份兼容语义变化**：学期可修改后，"term 不匹配拒绝恢复"从防御变成了常规路径（换学期后旧备份被拒）；发布说明需明确引导用户换学期时先导出新备份。
- **厂商闹钟差异**：提醒档位变化后需在真机复验（0.9 已有精确闹钟降级先例）；"关闭"档位要确认不再有残留闹钟。
