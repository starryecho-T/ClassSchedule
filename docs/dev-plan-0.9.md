## 功能 1：底部导航三 Tab

**目标**：MainActivity 从"单枢纽 + 菜单跳转"改为底部三 Tab 常驻切换，日程概览从二级页提升为一级页。

**实现要点**：

- `activity_main.xml` 改为 `BottomNavigationView` + Fragment 容器结构
- 新增三个 Fragment：
  - `ScheduleFragment`：包装现有 `TimetableView` 与周次切换逻辑（从 MainActivity 迁移）
  - `OverviewFragment`：迁移 `ScheduleOverviewActivity` 的日程列表内容
  - `MineFragment`：收纳现有溢出菜单项（教务导入、已隐藏课程、检查更新）
- 使用 `FragmentTransaction.show/hide` 切换，保留各 Tab 滚动位置与周次选择状态
- `MainViewModel` 提升为 Activity 级共享，三个 Fragment 复用同一数据流
- `EditCourseActivity`、`ImportActivity` 保持独立 Activity 不动（流程型页面不做 Tab）
- 优先复用已有 Material / Fragment 能力；若使用 `activityViewModels` 等 KTX 扩展，先核实依赖，不预先承诺零新增依赖

**手势分区约定**：左右滑动切周次仅作用于课表 Tab 内部；Tab 切换只通过底部点击，不做左右滑切页，避免手势冲突。

**验收标准**：

- [ ] 三 Tab 切换不丢失各自状态（周次选择、滚动位置）
- [ ] 日程概览数据与课表页实时同步（同一 ViewModel）
- [ ] "我的"页入口全部可用（导入 / 隐藏课程 / 备份 / 恢复 / 检查更新），展示版本号；不放不可用的设置占位按钮
- [ ] 课程块点击 → 详情弹窗 → 编辑页 → 返回后回到原 Tab 且数据已刷新
- [ ] 小组件、上课提醒广播路径不受影响（回归验证）

## 功能 2：JSON 备份 / 恢复

**目标**：课表数据可导出为 JSON 文件、从 JSON 恢复，换机 / 重装不丢数据。

**实现要点**：

- 导出：全量 `CourseEntity` → JSON（字段覆盖 name / teacher / room / dayOfWeek / startPeriod / endPeriod / weeks / hiddenWeeks / colorIndex），文件名含日期（如 `classschedule-backup-20261019.json`）
- 分发方式：本版只用 SAF `CreateDocument` 保存；系统分享与 `FileProvider` 延后
- 恢复：SAF `OpenDocument` 选取 → 完整解析校验 → 预览确认 → 备份专用 Room 事务写入。不能直接复用 `ImportPolicy`，因为它会清空 hiddenWeeks、trim 文本、重置 id 并去重
- 入口放"我的"页；导入失败回滚，不污染现有数据
- JSON 结构预留 `version` 字段，为 1.0 多学期管理铺路

**验收标准**：

- [ ] 导出文件可被自身恢复，往返（round-trip）无损
- [ ] 非法 / 损坏 JSON 有明确错误提示，不崩溃不写库
- [ ] 恢复走追加去重时，重复课程不产生新记录
- [ ] JVM 单测覆盖 JSON 编解码、反序列化和校验；实际测试数量以开工时重跑结果为准

## 功能 3：深色模式全面适配

**目标**：支持跟随系统及手动浅色 / 深色选择，重启后保留；统一页面与小组件的配色。

**现状**：`themes.xml` 已用 `Theme.Material3.DayNight`，`TimetableView` 内部已有 `isNight` 局部分支，但 Activity 布局、列表项、详情弹窗、小组件均未适配。

**实现要点**：

- 建立 `values-night/themes.xml`、`values-night/colors.xml` 资源体系，颜色统一走资源引用，消除布局中硬编码色值（如 `item_day_course.xml` 的 `darker_gray`）
- 逐页检查：课表页 / 日程页 / 我的页 / 编辑页 / 导入页 / 课程详情弹窗 / 周次选择器
- `CourseColors.kt` 调色板补深色变体（课程标签色在深色下降饱和、提亮度）
- `TimetableView` 中现有 `isNight` 硬编码色值迁移到资源
- 小组件 `widget_today.xml` 适配（受启动器限制，用 `@android:style/Widget` 亮暗两套或中性色）
- 遵循项目配色偏好：低饱和度、柔和，不用高饱和亮色

**验收标准**：

- [ ] 系统 dark / light 切换后所有页面即时正确（含重启后）
- [ ] 无硬编码白色背景、无深色背景上深色文字
- [ ] 课程标签色在两种模式下均可读（对比度检查）
- [ ] 小组件在深色桌面下无白块

## 实施补充与发布门槛（2026-10-19 修订）

### 总体评价与交付边界

三个功能的组合与顺序合理：先整理入口，再保护数据，最后统一视觉。需要加强的主要是备份语义、页面重建和回归验收。云同步、备份加密及系统分享仍不在本版；手动主题选择已按用户发布前要求纳入。

交付成功的标准是：原有课程操作全部可达、备份替换恢复保留课程状态、任何失败不产生半份课表、亮暗模式下关键流程可读可用。

### A. 导航状态与生命周期

- MainActivity 管理导航、共享 MainViewModel、通知权限和启动更新检查；切换 Tab 不重复弹出权限或自动更新提示。
- “我的”页提供教务导入、隐藏课程、备份、恢复、检查更新及版本信息；不展示不可用的设置占位按钮。
- 课表与日程共享课程数据，但各自保留浏览周次、日期和滚动位置；首次进入定位本周 / 今天，切 Tab 不强制同步日期。
- 点击课程保持现有“详情弹窗 → 编辑”路径；保留删除、隐藏、恢复和长按空白加课。添加按钮仅出现在适用页面。
- 系统返回先关闭弹窗或子页面；日程 / 我的返回课表，课表使用系统退出行为。重复点击当前 Tab 不重置页面，不积累 Tab 返回栈。
- 使用稳定 Fragment tag，重建时复用系统恢复的实例，避免重复 add。show/hide 之外明确管理生命周期：可见页 RESUMED、隐藏页最高 STARTED；可见页渲染按 viewLifecycleOwner 的 RESUMED 状态收集，避免隐藏列表反复重建。
- 选中 Tab、各页周次、日期及滚动位置必须通过 saved state 保存；普通 ViewModel 或 show/hide 不能代替进程重建恢复。列表重建完成后再恢复滚动位置。
- onDestroyView 解除 View 引用与回调；恢复前台时刷新“今天”标记，同时保留用户所选周次。
- 优先复用已有库，不引入 Navigation / ViewPager；使用 activityViewModels 等扩展前核实 KTX 依赖，撤销绝对“零新增依赖”的承诺。
- 移除旧日程入口时同步检查 Manifest、菜单与调用点；底部导航验证系统栏、手势导航、三键导航及横屏下无遮挡。

新增验收：

- [ ] 切 Tab、旋转、亮暗切换和后台进程回收后恢复任务，页面不重复且状态保留；进程回收与强制停止分别记录。
- [ ] 编辑 / 删除 / 隐藏在课表、日程与隐藏列表中一致；从导入或编辑返回来源 Tab。
- [ ] 首次启动、通知授权 / 拒绝、更新检查、长按加课及周次滑动无回归。

### B. 备份协议与无损边界

**代码发现：ImportPolicy.prepare 会清空 hiddenWeeksCsv、trim 文本、重置 id 并按自然键去重。备份恢复不能直接走这个清洗流程。**

引入独立 Backup DTO、编解码器、校验器与恢复策略；复用通用校验或自然键比较能力，但保持原有教务导入行为不变。周次以整数数组保存，不暴露 Room CSV 结构，不导出或沿用数据库主键。

首版建议协议（示例数据，不是用户课表）：

```json
{
  "format": "classschedule-backup",
  "version": 1,
  "appVersion": "0.9.0",
  "exportedAt": "2026-10-19T08:00:00Z",
  "term": { "startDate": "2026-09-07", "totalWeeks": 17, "periodsPerDay": 12 },
  "courses": [
    {
      "name": "示例课程", "teacher": "", "room": "",
      "dayOfWeek": 1, "startPeriod": 1, "endPeriod": 2,
      "weeks": [1, 2], "hiddenWeeks": [2], "colorIndex": 0
    }
  ]
}
```

- version 是协议版本，区别于应用版本；缺失或不支持则拒绝。支持版本中的未知附加字段可忽略。
- 学期信息仅作兼容检查，不修改硬编码校历；首版对开学日、总周数或每日节次不匹配的备份拒绝恢复并说明原因。
- 备份包含全部课程及隐藏状态，不包含通知权限、系统闹钟、WebView 登录态、小组件摆放或页面浏览状态。
- 无损指替换恢复前后课程记录多重集相同，包含原文本、颜色、隐藏周次和重复记录；不要求主键、记录顺序或导出时间相同。文本不得在恢复时被静默 trim。

| 模式 | 明确行为 | 确认信息 |
| --- | --- | --- |
| 追加去重（默认） | 自然键沿用名称、教师、教室、星期、节次及周次；保留已有记录及其颜色 / 隐藏状态，新记录采用备份字段 | 文件总数、预计新增与跳过数，说明不会覆盖已有隐藏状态 |
| 替换全部 | 同一事务删除旧记录并插入全部备份记录；不去重，重新生成 id | 将移除与恢复的数量、二次确认，并建议先备份现有课表 |

追加时文件内部相同自然键按顺序保留第一条，其余计为跳过并在预览说明；不清理数据库原有重复记录。

校验要求：

- 必需字段及 JSON 类型严格校验，不将字符串、小数、null 静默转换为合法整数。名称不能为空；教师和教室允许空字符串。
- 星期 1..7；节次满足 1 ≤ startPeriod ≤ endPeriod ≤ 每日节数；weeks 非空且在学期范围内，hiddenWeeks 必须是 weeks 子集。
- 周次数组按集合语义排序、去重；范围外数据整批拒绝。colorIndex 为非负 Int，保留索引，渲染按调色板长度取模。
- 任意一条非法则整批拒绝，报告记录序号与字段原因，不静默跳过坏记录。
- 建议保护上限为 UTF-8 文件 5 MiB、10,000 条课程、每个文本字段 4,096 字符；实施时验证正常数据适用性。流读取过程中执行上限，不只信任文件元数据。
- 空课表允许导出；本版空备份仅可查看，恢复不写库，不能以替换空备份清空已有数据。
- 导出前也验证快照；遇到存量非法数据明确报错，避免生成自身无法恢复的备份。

### C. 文件与事务流程

- 本版只实现 SAF CreateDocument / OpenDocument，MIME 为 application/json；分享与 FileProvider 延后，不申请广泛存储权限。默认文件名包含本地日期时间，JSON 时间含明确时区。
- 从仓库一次性读取完整快照，不能把 StateFlow 初始空列表当作实际课表。文件读取、编码与解析离开主线程。
- 流程：选择文件 → 有界读取 → 完整校验 → 预览 → 明确确认 → 事务写入 → 实际结果。取消或校验失败不修改课程。
- 新增备份专用仓库 / DAO 事务入口，沿用 CourseRepository 共享 mutationMutex 和初始化保护，避免与启动 seed 竞争或误用教务导入清洗流程。
- 追加模式在事务内重新读取现有数据并去重，显示实际新增 / 跳过数。替换预览后数据若变化，重新预览与确认，不能删除未被用户确认的新课程。
- 写入期间禁止重复提交，旋转后保留进度；提交成功后不能因 UI 重建再次执行。插入失败由 Room 回滚，不留下半份课表。
- 数据库与初始化 SharedPreferences 不属于同一事务；现有仓库先写初始化标记，不能承诺跨存储原子回滚。需验证恢复 / 首次启动并发时不会重新注入示例。
- 导出仅在写入和关闭流成功后提示完成；存储不足、URI 失效、提供方离线或部分写入均报告失败，提醒残留文件可能不完整。
- 恢复成功后沿用 ScheduleApp 的 Room 观察链路刷新小组件、重算提醒；同时验证两页内容更新，未授权通知时不宣称提醒可送达。
- 明文备份的保管说明放在 README 与发布说明；按用户要求不在“我的”页常驻展示。日志不记录整份备份或登录数据。

新增验收：

- [ ] 普通 / 部分隐藏 / 全部隐藏课程、颜色、中文特殊字符、原文本及重复记录通过替换往返测试。
- [ ] 同一文件追加两次不增加重复记录，已有隐藏状态与颜色保持。
- [ ] 空文件、空课表、损坏 JSON、缺字段、错误类型、未来协议、学期不匹配和超限输入结果明确。
- [ ] 取消、读取失败、导出失败、插入失败、重复点击及进程中断不产生半份课表、不误报成功。
- [ ] 用真实 Room 测试验证插入失败回滚；Fake DAO 策略测试不能证明实际事务行为。
- [ ] 编解码与校验可独立测试；先明确 JSON 依赖及 JVM 测试支持。若使用 Android JSON API，配置真实测试实现或设备测试，不依赖未实现的 android.jar 桩，也不手写正则 JSON 解析器。

### D. 深色适配补充

现有代码已采用 DayNight，日程部分颜色也使用主题属性，因此采用审计缺口方式逐页修复。优先主题语义色，自定义色增加 values/colors.xml 和 values-night/colors.xml；仅需要覆盖主题属性时才新增夜间 themes.xml。

- CourseColors 统一按当前配置取色，覆盖课表、日程、编辑配色及详情；保持索引顺序一致，不迁移存量索引。
- 自绘课表同时检查课程背景、文字、网格、今天列和透明叠色的最终可读性。项目验收目标：普通文字对比度至少 4.5:1，大字至少 3:1；选中态不只依赖颜色。
- 小组件使用自身资源及 values-night 颜色，包括 widget_bg；不要以通用 Widget 样式替代适配。验证系统主题变化后的 RemoteViews 重建，必要时补刷新触发，记录启动器差异。壁纸颜色不能作为系统深色状态。
- 覆盖备份预览、进度、错误、隐藏课程列表及系统栏。第三方教务网页单列限制，不通过强制反色破坏验证码和网页内容。
- 验证大字体、窄屏和横屏下操作可达；底部 Tab 保留文字标签，图标提供无障碍描述。
